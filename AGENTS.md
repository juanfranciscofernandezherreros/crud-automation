# crud-automation — Spring generation rules

These rules describe the contract for Spring Boot code generated by the `feature` architecture.
They apply to the generator, templates, generated fixtures, and tests. They are **not copied into generated microservices**.

## Feature package layout

Generated CRUD code is grouped by feature:

```text
com/<company>/<app>/<feature>/
  controller/   <Feature>Controller
  service/      <Feature>Service
                <Feature>ServiceImpl
  repository/   <Feature>Repository
                <Feature>Specifications
  model/        <Feature>, enums
  entity/       <Feature>Entity
  dto/          <Feature>CreateDTO
                <Feature>UpdateDTO
                <Feature>PatchDTO
                <Feature>ResponseDTO
  mapper/       <Feature>Mapper
                <Feature>EntityMapper
```

## Layer responsibilities

- `controller`: bind and validate HTTP input, map DTO -> model, call the service, map model -> DTO.
- `service`: business orchestration, transactions, not-found handling, pagination/filtering orchestration.
- `repository`: Spring Data interfaces and persistence specifications only.
- `model`: framework-free in-memory representation; no `jakarta.persistence` imports.
- `entity`: JPA persistence mapping only; no controller/business behavior.
- `mapper`: field mapping only; no repository/service/I/O access.

## Required generation rules

1. Generate one service interface and one implementation. Keep both in `service/`; do not create `service/impl/`.
2. Controllers depend on the service interface. Service unit tests target the implementation with `@InjectMocks`.
3. Generate a persistence-free model and a distinct `<Feature>Entity` JPA class.
4. Generate two mappers consistently:
   - `<Feature>Mapper`: DTO <-> model.
   - `<Feature>EntityMapper`: model <-> entity.
5. Repositories are plain Spring Data interfaces; do not add `@Repository` for ordinary CRUD.
6. Put `@Transactional` at service-class level and use `@Transactional(readOnly = true)` on read paths.
7. Use `var` for controller/test locals. Use explicit local types in services and mappers.
8. Keep controller statements separate: request mapping, service call, and response mapping must not be nested into one expression.
9. Controllers do not perform repository access, existence checks, or business branching.
10. Generated models must never import JPA annotations.

## Tests that enforce the contract

`tests/test_feature_generator.py` is the executable contract for these rules. Any change to the feature architecture must update those tests deliberately rather than weakening them accidentally.

The acceptance test also compiles and runs the generated Maven project when Maven is available.

## CLI

Generate with:

```bash
python -m crud_generator Producto "id:int,nombre:string,precio:decimal" --architecture feature
```

`--feature` is accepted as a shorter alias.

Existing `layered`, `hexagonal`, `clean`, and `minimal` modes remain unchanged until a deliberate migration is made.
